02 · Two Phases

Prefill 与 Decode，不是同一种工作负载

首轮更擅长并行；逐 Token 解码则具有严格的先后依赖，无法一次把整段答案算出来。
● PREFILL · 提示词预填充

Prompt 一次进入

Prompt 中所有位置组成一个矩阵，通过因果 Mask 并行处理。每一层把各位置的 K/V 写入缓存，并用最后位置的隐藏状态预测第一个输出 Token。

法国的首都是
矩阵较大，GPU 并行度高耗时通常体现为 TTFT（首 Token 延迟）Prompt 越长，Prefill 工作越多
● DECODE · 自回归解码

每轮只向前一步

把上一轮刚选出的 Token 作为本轮输入，只计算它的新 Q/K/V；新 K/V 追加到缓存，Q 则读取所有历史 K/V，最后再预测下一个 Token。

巴黎 →
生成 N 个 Token 至少需要 N 次串行前向传播每轮都要读取模型权重，常受显存带宽限制上下文越长，注意力读取的 KV 越多
O(n²) → O(n)
KV Cache 省的是重复投影

不再为每个历史 Token 重算各层 K/V。但新 Query 仍需扫描历史 K/V，所以单步注意力并不是 O(1)。

K,V ≠ Q
为什么不缓存 Query？

历史 Query 完成当时那一步后不再需要；未来 Token 只需用自己的 Q 去匹配历史 K，并汇总历史 V。

× batch
缓存属于每个请求

并发数、上下文长度、层数、KV Head 数和缓存精度都会直接放大 KV Cache 显存占用。

1M 上下文，不只是把参数改大

!
1M 窗口 ≠ 1M 内容都能被同等理解

模型必须经过长序列继续训练并验证位置外推；还要测试 Lost-in-the-Middle、Needle-in-a-Haystack、RULER 等任务。只修改 max_position_embeddings 或 RoPE scale 通常不够。

①位置编码与训练

通过原生长序列训练，或 Position Interpolation、NTK-aware、YaRN、LongRoPE 等扩展 RoPE。外推必须配合数据和评测。

②高效 Attention

FlashAttention 降低中间显存；Ring/Context Parallel 分摊精确 Attention；Sliding/Block Sparse 才真正减少计算，但会改变可见范围。

③Chunked Prefill

把 1M Prompt 切成可调度小块，降低峰值并避免长 Prefill 阻塞 Decode。它不等于减少总计算量。

④KV Cache 工程

依靠 GQA/MQA、KV 量化、Paged KV、Context Parallel、Prefix 复用，以及 GPU→CPU→SSD 分层管理线性增长的缓存。

⑤不要忘记 RAG

1M Context 适合全局代码库、长视频和文档；普通问答通常先检索再放入较短窗口，成本和有效注意力往往更好。

07 · Quantization Lab

Q4、Q8 到底把数字变成了什么？

移动原始权重，观察它如何“吸附”到最近的离散等级。Q4 是约 4 bit，不是 4 字节或 4 位小数；Q8 也不等于 FP8。

Q6_K高质量压缩

比 Q8 更小，通常仍非常接近高精度模型。

Q5_K_M偏向质量的折中

重要张量获得更多精度，适合显存稍宽裕的部署。

常用起点Q4_K_M质量与体积均衡

K-Quant 混合精度格式；并非每个张量都严格使用相同 4 bit。

Q3 / Q2极限压缩

能装入更小显存，但等级更少、误差更大，质量下降风险明显。

一句话：离散等级就是每个 Group 中允许使用的有限候选值。Q4 有 2⁴=16 个编码，Q8 有 2⁸=256 个编码；每组使用自己的 Scale，因此不是整个模型只能出现 16 或 256 个实际数值。

一句话记住整个过程

模型读取当前输入 → 每层产生新 Q/K/V → 把 K/V 追加进缓存 → 当前 Q 读取全部历史 K/V → MLP 变换 → LM Head 得到词表 Logits → 采样一个 Token → 把它作为下一轮输入，周而复始。
