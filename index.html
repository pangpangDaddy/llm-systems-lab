02 · Two Phases

Prefill 与 Decode，不是同一种工作负载

首轮更擅长并行；逐 Token 解码则具有严格的先后依赖，无法一次把整段答案算出来。
● PREFILL · 提示词预填充

Prompt 一次进入

Prompt 中所有位置组成一个矩阵，通过因果 Mask 并行处理。每一层把各位置的 K/V 写入缓存，并用最后位置的隐藏状态预测第一个输出 Token。

法国的首都是
矩阵较大，GPU 并行度高耗时通常体现为 TTFT（首 Token 延迟）Prompt 越长，Prefill 工作越多
● DECODE · 自回归解码

每轮只向前一步

把上一轮刚选出的 Token 作为本轮输入，只计算它的新 Q/K/V；新 K/V 追加到缓存，Q 则读取所有历史 K/V，最后再预测下一个 Token。

巴黎 →
生成 N 个 Token 至少需要 N 次串行前向传播每轮都要读取模型权重，常受显存带宽限制上下文越长，注意力读取的 KV 越多
O(n²) → O(n)
KV Cache 省的是重复投影

不再为每个历史 Token 重算各层 K/V。但新 Query 仍需扫描历史 K/V，所以单步注意力并不是 O(1)。

K,V ≠ Q
为什么不缓存 Query？

历史 Query 完成当时那一步后不再需要；未来 Token 只需用自己的 Q 去匹配历史 K，并汇总历史 V。

× batch
缓存属于每个请求

并发数、上下文长度、层数、KV Head 数和缓存精度都会直接放大 KV Cache 显存占用。

▦Paged Allocation

按固定 Block 分配，避免为每条序列预留整段连续显存，并减少碎片。

⇶Continuous Batch

每个 Decode 时钟把所有活跃序列的新 Token 合并成一批执行。

⌘Prefix Sharing

完全相同的 Token 前缀共享不可变 KV Block，并通过引用计数保护。

↧LRU & Offload

只淘汰无活跃引用的冷 Block；需要时从 CPU/SSD 恢复而非重算。

P→DKV Transfer

Prefill 节点产生 KV，Decode 节点接收后继续逐 Token 生成。
